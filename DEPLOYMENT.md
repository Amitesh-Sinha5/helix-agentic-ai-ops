# Deploying Helix

Two supported paths:

- **[Split deployment](#split-deployment)** — Vercel (frontend) + Render (backend) + Neon (Postgres) + Upstash (Redis). This is the recommended route and the one the config files in this repo are written for.
- **[Containers](#containers)** — the same images on Kubernetes or Azure Container Apps.

---

## Why the backend cannot be serverless

Helix's API needs a long-lived process. Three things depend on it:

1. **WebSockets.** `/ws/agent-status/{id}` and `/ws/admin/escalations` hold connections open for the life of a request (and indefinitely, for admins).
2. **Chroma.** The vector index is an on-disk store the process opens directly. It needs a persistent disk, not ephemeral function storage.
3. **LangGraph state.** An agent run spans several LLM calls inside one request; a serverless timeout mid-graph loses the work.

So: Vercel for the static frontend, a real container/VM for the API.

## Split deployment

### 1. Postgres (Neon or Supabase)

Create a database and copy the connection string. **It must be rewritten for asyncpg:**

```
# What the provider gives you:
postgresql://user:pass@host/db?sslmode=require

# What Helix needs (note the +asyncpg driver, and no sslmode param):
postgresql+asyncpg://user:pass@host/db
```

`sslmode` is a libpq option that asyncpg does not accept and will reject. Neon requires TLS anyway, and asyncpg negotiates it automatically. If you need to be explicit, use `?ssl=require`.

### 2. Redis (Upstash)

Create a database and copy the **`rediss://`** (TLS) URL. Set `REDIS_REQUIRED=true` in production so a Redis outage fails loudly instead of silently degrading to the in-process fallback — which would make the semantic cache and rate limits per-instance and wrong.

### 3. Backend (Render)

Point Render at this repo. It reads [`backend/render.yaml`](backend/render.yaml), which already sets the build, migration and start commands plus the persistent disk for Chroma.

Set these in the dashboard (they are marked `sync: false` and are never committed):

| Variable | Value |
|---|---|
| `DATABASE_URL` | the `postgresql+asyncpg://…` string from step 1 |
| `REDIS_URL` | the `rediss://…` string from step 2 |
| `REDIS_REQUIRED` | `true` |
| `LLM_PROVIDER` | `anthropic` or `openai` |
| `ANTHROPIC_API_KEY` / `OPENAI_API_KEY` | your key |
| `EMBEDDING_PROVIDER` | `openai` (needs `OPENAI_API_KEY`), or `mock` |
| `CORS_ORIGINS` | exactly your Vercel domain, e.g. `https://helix.vercel.app` |
| `BILLING_SUCCESS_URL` | `https://<your-vercel-domain>/billing?status=success` |
| `BILLING_CANCEL_URL` | `https://<your-vercel-domain>/billing?status=cancelled` |
| `STRIPE_SECRET_KEY` | `sk_test_…` |
| `STRIPE_WEBHOOK_SECRET` | from step 6 |
| `STRIPE_PRICE_ID_PRO` | the price id of your Pro product |
| `COST_PER_1K_PROMPT_TOKENS` | your model's real price — otherwise the cost dashboard is fiction |
| `COST_PER_1K_COMPLETION_TOKENS` | as above |

`JWT_SECRET_KEY` is generated by Render automatically. Rotating it invalidates every existing session.

Migrations run in `preDeployCommand` (`alembic upgrade head`), before the new instance takes traffic. That is why `RUN_MIGRATIONS=false` is set — the container entrypoint must not also try, or two instances would race.

### 4. Frontend (Vercel)

Import the repo, set **Root Directory** to `frontend/`. [`frontend/vercel.json`](frontend/vercel.json) supplies the build config, SPA rewrites and cache headers.

Set one environment variable:

| Variable | Value |
|---|---|
| `VITE_API_URL` | `https://<your-render-service>.onrender.com` |

**Vite inlines `VITE_*` at build time.** Changing it requires a redeploy, not a restart. If the frontend cannot reach the API after a change, this is almost always why.

### 5. Create the admin account

The **first account created on a fresh instance becomes the administrator.** Immediately after the first deploy, go to `/signup` and create your own account before anyone else does.

### 6. Stripe webhook

In the Stripe dashboard → Developers → Webhooks → Add endpoint:

- **URL:** `https://<your-render-service>.onrender.com/billing/webhook`
- **Events:** `checkout.session.completed`, `customer.subscription.updated`, `customer.subscription.deleted`

Copy the signing secret into `STRIPE_WEBHOOK_SECRET` and redeploy.

The webhook endpoint is unauthenticated by necessity — Stripe cannot present a JWT — so **the signature is the authentication.** With `STRIPE_WEBHOOK_SECRET` unset, Helix accepts unsigned payloads (that is what makes local development work), which in production would let anyone upgrade themselves to Pro. Setting it is not optional.

Verify with the Stripe CLI:

```bash
stripe listen --forward-to https://<your-service>.onrender.com/billing/webhook
stripe trigger checkout.session.completed
```

### 7. Verify

```bash
python scripts/smoke_test.py https://<your-render-service>.onrender.com
```

Ten checks across health, auth, all three pods, caching, RBAC and billing. Non-zero exit on any failure, so it works as a post-deploy gate.

## Containers

Both images build from a clean checkout and are verified in CI.

```bash
docker compose up --build      # the whole stack locally
python scripts/smoke_test.py   # 10/10 against it
```

### Kubernetes

```bash
kubectl apply -f infra/k8s/
```

[`infra/k8s/`](infra/k8s/) contains the Deployments, Services, an HPA (2–10 replicas on CPU/memory), a PodDisruptionBudget, and an Ingress. Three things to know before applying:

- **Migrations run as a Job**, not in the entrypoint (`RUN_MIGRATIONS=false` in the ConfigMap). Replicas must not race to migrate the same database.
- **The Ingress splits by host, not path.** `helix.example.com` serves the SPA, `api.helix.example.com` serves the API. They cannot share a host: `/billing`, `/support`, `/observability` and `/code-review` are each both a client-side route and an API route, so path-based routing would send users to JSON instead of a page.
- **The Chroma PVC is `ReadWriteMany`** because replicas share one index. On a provider without RWX volumes, run Chroma as its own service instead.

Replace `ghcr.io/OWNER/…` with your registry, and supply real secrets through External Secrets or your cloud's secret store rather than the placeholder `Secret` manifest.

### Azure Container Apps

```bash
cd infra/terraform
terraform init
terraform apply -var="postgres_password=…" -var="jwt_secret=…"
```

Provisions Postgres Flexible Server, Azure Cache for Redis, a container registry, and both apps. `terraform output next_steps` prints the image build/push commands with the right registry substituted in.

The backend scales on **HTTP concurrency, not CPU** — agent requests spend their time waiting on the model, so CPU stays low even when the service is saturated.

## Production checklist

- [ ] `CORS_ORIGINS` is exactly your frontend domain — no `*`, no trailing slash
- [ ] `JWT_SECRET_KEY` is a generated 32+ character secret, not the dev default
- [ ] `STRIPE_WEBHOOK_SECRET` is set (see step 6 for why this matters)
- [ ] `REDIS_REQUIRED=true` so a Redis outage fails loudly
- [ ] `DEBUG=false` and `ENVIRONMENT=production`
- [ ] `COST_PER_1K_*` match your model's real prices
- [ ] You created the first account, so you hold the admin role
- [ ] `python scripts/smoke_test.py <url>` passes
- [ ] Postgres backups are on (Neon and Render Postgres do this by default)

## Troubleshooting

| Symptom | Cause |
|---|---|
| `sslmode is an invalid keyword argument` | `DATABASE_URL` still has `?sslmode=require`; asyncpg does not accept it |
| `InvalidCatalogNameError` / no tables | Migrations did not run — check `preDeployCommand` output |
| Frontend loads, every API call fails CORS | `CORS_ORIGINS` does not exactly match the frontend origin |
| Frontend calls `localhost:8000` in production | `VITE_API_URL` was not set **at build time**; redeploy |
| Live agent trace never appears | Proxy is closing the WebSocket — raise `proxy_read_timeout` |
| Upgrades never apply | Webhook not registered, or the signature check is rejecting it; check Stripe's delivery log |
| Rate limits reset unpredictably | Redis unreachable and silently falling back per-instance; set `REDIS_REQUIRED=true` |
